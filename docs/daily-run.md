# 每日执行规则

运行入口：`python ribao.py run`。定时采用 Windows 任务计划程序，不依赖 Codex 或聊天上下文。运行前项目维护者先完整读取三个持续入口。

## 流程

1. 取 UTC+8 当前日期的前一天，读取 settings.json 和本机凭据。
2. 按目标 Webhook 读取近 30 天实际投递历史。三个新闻板块分别调用北京百炼 qwen-plus，强制联网并返回真实搜索来源。先做 8 次昨日主题检索，使用 max 策略，提示优先参考主题站点，在本地排除低相关页面和已发链接。检索回答的自由文本不用作条目或链接。
3. 保存百炼原始响应、usage 与来源到 data/日期/。未返回有效搜索来源视为采集故障，即使模型声称没有新闻也不改为“暂无”。
4. 按搜索来源列表读取公开原文，校对日期元数据或明确发布日期标签；对可识别的证券日报电子报同时支持期号日期。日期不明、矛盾、正文不可访问、非公开 URL 均排除。保存正文与识别结果到 pages/ 和各板块 sources.json。链接绝不采用模型补写的地址。
5. 有可用正文的板块再调用一次非联网模型整理，显式给出正文、来源编号和已发主题。模型只能返回编号；程序填写链接、发布方和日期。每条需有能在正文中逐字匹配的连续证据，缺证据或引用未知编号均拒绝。采购截止时间再次检查。原文发表于昨日，不等于文中事件均发生在昨日；摘要应忠实区分。
6. 每栏优先昨日条目，按实际日期和编辑优先级排序，依据链接、事件标识和标题跨板块、跨天去重。少于 10 条时各补做最多一次月内检索和正文整理，接受截至昨日的最近 30 天公开资料，仍不足按实际展示。三个新闻板块总计最多 11 次检索、6 次整理；同一篇当日汇总中的不同事件可分别推荐，历史已发汇总的 URL 则整体排除，避免重复补位。
7. GitHub 第四栏读取官方公开仓库搜索：优先昨日有更新的非 fork、未归档且累计星标不少于 100 的项目，按累计星标排序；不足时查询近 30 天，累计最多两次搜索。排除已发仓库后，读取公开 README（原始文件优先，失败回退 API，每项目最多两次），连同简介切为固定编号片段，一次百炼非联网调用批量生成中文用途、人群和具体场景。模型只选事实编号，程序绑定逐字原文和项目元数据；资料不足的项目排除，不退回英文简介。解释按输入和模型配置缓存，不变时重用。全量生成最多 18 次百炼调用。
8. 写入 report.json、preview.md、cards.json。四栏各一张飞书卡片，单张检查 UTF-8 字节大小。每条末尾附原文或仓库链接；过滤原因、跳过数量和调试说明只存本地。完整空结果写“暂无”；整栏故障仅显示简短失败提示。
9. 按 Webhook 指纹隔离投递回执。提交前记录 uncertain 及 items_by_part 条目快照，成功后改为 sent。已发卡片自动跳过，明确拒绝的卡片可再次尝试。网络超时、进程中断或响应不明确时保留 uncertain，人工检查群后再恢复。历史去重只采纳 sent/uncertain，不计入预览或明确失败的条目。

## 异常恢复

程序退出码：0 成功，1 配置/投递/文件异常，2 报告含采集故障。任务计划程序的“上次运行结果”和 data/logs/ 可查结果。本版没有独立的管理员告警渠道；群内可能收到部分采集失败说明，飞书完全不可达时只留下本地失败记录。

正常 run 会复用当日已生成报告，便于中断恢复、避免重复 API 计费。若报告采集失败需要重新生成，在确认当日没有任何已发送或 uncertain 投递记录后，执行 `python ribao.py run --refresh --preview-only`。已有投递记录时停止刷新，先人工核实。

已投递报告需要诊断或修复时，`python ribao.py rebuild-preview` 复用当日原始检索，另建 data/日期/review/ 预览；缺少月内检索缓存时最多追加 3 次检索，加最多 6 次正文整理，以及 GitHub 公开查询。此命令不向群发送、不改变原回执；历史去重会排除之前发过的条目。该目录保留修复证据；不能通过删除回执绕过重复发送保护。

用户要求补发昨日修正版时，运行 `python ribao.py resend`：复用 review/report.json，不调用模型，卡片标注“修正版”，按内容生成编号，保存到 revisions/编号/ 并使用独立投递回执。同一修正版仅发送一次；出错重跑可续发。修正版 uncertain 状态的人工核验使用 recover 的 `--revision 编号` 参数，不修改原版回执。

只调整一个板块时可加 `--section github_hot`（或其他板块 ID），并用 `--input` 指定已完成的完整报告。只投递该栏，回执保留原卡片编号，例如 GitHub 仍为第 4 张；恢复时也用 --part 4。同一单栏修正版重复执行自动跳过。

若投递结果不确定，检查群内对应卡片：

```powershell
# 第 1 张实际已经收到
python ribao.py recover --part 1 --resolution sent
# 第 1 张实际没有收到
python ribao.py recover --part 1 --resolution retry
python ribao.py run
```

任务锁遗留时，先核对没有本项目的 Python 进程在运行，再移除 `.local/run.lock`。不要自动删除锁或 uncertain 回执。

## 质量边界

仅搜索公开资料，不登录、不绕过验证码、不自动联系任何发布方。搜索索引存在延迟，不能保证穷尽近期信息；日期元数据和模型判断也可能有误，原文链接始终保留以便回查。日期校验只验证网页可识别的发布时间，不等于独立验证全文事实或采购方资质。标题改写和多站转载的语义去重可能遗漏，不能把“通过程序检查”称为人工核验。

财商内容是信息与解释；供应广告保留 supply 标签，不计为求购。外贸板块只接受具体丝网相关发布，不把宏观趋势冒充采购订单。

## 接口依据

- [百炼联网搜索](https://help.aliyun.com/zh/model-studio/web-search)：DashScope 原生文本接口、强制检索、来源返回。
- [百炼结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)：JSON Object 与关闭思考模式。
- [飞书自定义机器人](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot?lang=zh-CN)：签名、业务响应、消息大小限制。
- [GitHub 仓库搜索](https://docs.github.com/en/rest/search/search#search-repositories)：公开仓库搜索、星标排序和 pushed 时间筛选。
